# 0032 - Fourth wave of player value (Nov 2026)

Date 2026-11-17. Research 0020, 0023, 0028 and 0031 rows are done
(campaign, maps, deaths, trades, item checks with PoB deltas, prices,
filters, build health, skill split, waystone rewards, campaign checks).
This note looks for the remaining high-value gaps inside the ToS floor
(CLAUDE.md, decisions 0003, 0004, 0009, 0013, 0014) from four angles:
(a) onboarding a brand-new free-to-play 1.0 player, (b) endgame / atlas
signals from Client.txt alone, (c) reliability (self-diagnostics), (d)
non-English game clients. Ranked 6 candidates (section 5); floor cases
J / K / L ruled by the adjudicator on 2026-11-17 (section 6); top 4 filed
as ROADMAP rows (section 7). Companion tools are studied for ideas only;
no code read or copied.

## 1. Onboarding a new free-to-play player (first 30 minutes)

- 1.0 goes free-to-play on 2026-12-11 (research 0021 section 1). The
  newcomer arrives with no PoB build and no Client.txt history, so every
  build-based card (health, look-for-next, item check verdicts) is empty
  for them; only the log-driven cards have anything to show.
- Beginner lists repeat the same few lessons: vendors refresh stock on
  level-up, start from a proven build, keep useful uniques (mein-mmo,
  "12 mistakes in Path of Exile 2 that you should avoid as a newcomer",
  2025-09-05,
  https://mein-mmo.de/en/path-of-exile-2-fehler-neulinge,1523931 ,
  accessed 2026-11-17); flasks are undervalued, the passive tree is a
  priority, resistances should be capped by Act 3, gold matters for
  respecs, rarity is not quality, learn the dodge roll (Mobalytics
  beginner tips https://mobalytics.gg/poe-2/guides/beginner-tips ,
  Vulkk https://vulkk.com/2024/12/19/path-of-exile-2-dos-and-donts-tips-for-beginners/ ,
  Sportskeeda https://sportskeeda.com/mmo/path-exile-2-poe2-best-beginner-tips-tricks-top ;
  search snippets, accessed 2026-11-17). None of these sources is about
  1.0 itself; all predate it.
- Death penalty: campaign deaths cost no experience; endgame map deaths
  cost 10 percent (sources disagree whether of the whole bar or of the
  current level; one Steam post reports 20 percent) (gfinity,
  https://www.gfinityesports.com/article/path-of-exile-2-how-does-the-death-penalty-work ;
  game8, https://game8.co/games/Path-of-Exile-2/archives/494914 ;
  Sportskeeda, https://sportskeeda.com/mmo/path-exile-2-poe2-death-penalty-dying-effect ;
  search snippets, accessed 2026-11-17). The poe2wiki Character death page
  refused the fetch (bot wall, 2026-11-17). Exact figure UNVERIFIED for
  1.0; a hint may state only "campaign deaths cost no experience, map
  deaths cost experience" until patch notes give the number.
- What AshLight can say with zero clicks, from Client.txt events alone:
  first level-up of a fresh character (level 2), first death, first town
  / hideout, first map area id, act-boss zone entry (UTIL-CAMPAIGN-CHECKS
  already covers resists there). Plus AshLight's own onboarding: the item
  check hotkey is the feature a newcomer will not discover unaided.

## 2. Endgame / atlas signals from Client.txt alone

- The log gives `Generating level N area "<id>" with seed N` for every
  instance (research 0002; forum example "Generating level 20 area
  "HideoutTemplarLab" with seed 1", search snippet,
  https://webcdn.pathofexile.com/forum/view-thread/3878401 , accessed
  2026-11-17). UTIL-MAPS already turns `Map*` ids into runs with time and
  deaths, and maps per hour.
- Not yet used: the area LEVEL of each map. Over a session or the run
  history it gives a progression ladder: highest map area level reached,
  maps and deaths per area level, time per map per level, and level-ups
  earned in maps. All of it is stated fact from lines the core already
  parses; no new log line, no unverified id.
- Still unknown: tower / citadel / pinnacle ids and any map-complete or
  boss-kill line (research 0002 section 4: no source; a forum request asks
  GGG for better logging, https://web.poecdn.com/forum/view-thread/3822995 ,
  title only, page 403 on 2026-11-17). 1.0 changes the atlas again
  (research 0021). UTIL-ATLAS-PROGRESS (research 0031) stays listed until a
  live endgame log exists.

## 3. Reliability: self-diagnostics

The facts a player needs when "nothing shows up" are already in the core
but spread over several pills and cards: tailer state (consented,
reading, path, idle, last line), web_data and contact (core.py), the price
book (pricebook.py / ninja.py fetch time and error), the calc component
(theorycraft/bridge.status, config/tc_pins.json), build-time data
snapshots in the sidecar cache, overlay / supervisor (procs.status,
keepalive health_check), the hotkey registration and the build stamp. No
one place answers "is AshLight healthy, and what do I do if not". Every
check is a local read; the fix lines point at scripts the repo already
has (setup.ps1 -TcCalc, run.ps1, the consent button, the web-data box).
A plain-text report the player copies on click makes support possible
without screenshots.

## 4. Non-English game clients

- PoE2 ships in nine languages: English, French, German, Spanish,
  Japanese, Korean, Portuguese (Brazil), Russian, Thai (LagoFast,
  https://www.lagofast.com/en/blog/path-of-exile-2-game-translation/ ,
  search snippet, accessed 2026-11-17); Traditional Chinese has a
  separate client with its own localisation complaints
  (https://web.poecdn.com/forum/view-thread/3912116 , search snippet,
  accessed 2026-11-17). poe.ninja localised its site into ten languages
  for both games (https://poe.ninja/posts/now-available-in-10-languages ,
  accessed 2026-11-17), a sign of real non-English demand.
- Does Client.txt change language? Research 0002 section 5: structural
  parts (prefix, `Generating level`, `[SCENE]`) are language independent;
  `You have entered`, `is now level`, `has been slain`, AFK / DND, whisper
  trade templates and party lines are language dependent (poefire needs
  the English client; whisper parsing failed for Russian clients). A
  2026-11-17 search found no localised PoE2 log sample (UNVERIFIED which
  exact strings change). Exile-UI ships "language packs" for non-English
  clients (search snippet, https://fr.github.com/Lailloken/Lailloken-UI ,
  accessed 2026-11-17); Exiled Exchange 2's FAQ says a language "would need
  the app_i18n file to be translated"
  (https://kvan7.github.io/Exiled-Exchange-2/faq , accessed 2026-11-17).
- What breaks in AshLight today (server/al/parser.py regexes, read
  2026-11-17): ENTERED (zone display name), LEVEL_UP (level, pace, under-
  level, campaign checks, multi-character), DEATH (death recap, map
  deaths), AFK / DND, JOINED / LEFT, TRADE_ACCEPTED / CANCELLED, the trade
  whisper templates (trade cards), and the item clipboard parser
  (theorycraft/item.py already flags "not an English PoE item text").
  What still works: zone ids and area levels (AREA_GEN), act splits and
  map runs (acts.py / runs.py work from ids), the scene clock (scene names
  may be localised, UNVERIFIED), whispers as raw chat (`@From` prefix is
  UNVERIFIED for other languages).
- Today a non-English player sees a half-working dashboard with no
  explanation. Per-locale pattern packs (research 0002's policy) need
  real localised log lines, which no source gives; a detector does not.

## 5. Ranked candidates

1. Self-diagnostics card (DIAG-SELF). One "Checks" card: Client.txt
   found / consented / reading / last line age, character seen, log
   language looks English (item 2), web data on and contact set, price
   book age and last error, calc component installed and pinned, data
   snapshots present and age, overlay and supervisor alive, hotkey
   registered, version. Each failing check carries a one-line fix. Folded
   to one "All checks pass" line when green; opens itself on a failure.
   "Copy report" writes a redacted plain-text report on the player's
   click. Floor: see ruling J. Data: local core state only. Size: medium.
   Value: high; removes the top support question for every new user.
2. Non-English client detector (LANG-GUARD). Area generations arrive but
   the English `You have entered` line does not follow for 3 area loads
   in a row -> one notice: which features need English game text and
   which still work. Floor: see ruling K. Data: Client.txt. Size: small.
   Value: high for the 1.0 intake in nine languages; turns silent breakage
   into one honest sentence.
3. First-hours hints (NEWBIE-HINTS). One-time, auto-expiring hints for a
   new character keyed to log events (first level-up from 1, first death,
   first town / hideout, first map, first item-check opportunity),
   AshLight-authored restated facts. Floor: see ruling L. Data: Client.txt
   events. Size: medium. Value: high for F2P newcomers, nil for veterans
   (hidden once a character passes level 2 without a fresh start).
4. Map level ladder (UTIL-MAP-LADDER). From the area level of each map
   run: highest map level reached, maps / deaths / median time per area
   level, level-ups earned in maps; this session and, with run history on,
   all sessions. Floor: YES - covered by ruling I (research 0031): the
   "Generating level" lines only, history in gitignored ops/runtime under
   the existing run-history opt-in. Data: Client.txt. Size: small-medium.
   Value: medium-high; the one endgame progression signal the log
   reliably carries.
5. Atlas progress (UTIL-ATLAS-PROGRESS, research 0031 item 6). Towers /
   citadels / bosses from ids. Floor: YES (ruling I). BLOCKED on a live
   endgame 1.0 log; listed only.
6. Per-locale log pattern packs (LANG-PACKS). Parse the language-
   dependent lines in the other eight languages. Floor: YES (Client.txt
   only). BLOCKED: no localised log sample exists in any source; needs
   volunteer logs or a live check per language. Listed only; LANG-GUARD
   is the honest stop-gap.

Not feasible under the floor: reading the game's language setting from
its config file or registry is a game-file read outside the Client.txt
allowance (decision 0003 lists what may be read), so the language is
inferred from the log only; reading tutorial state or quest state (no log
line, memory or screen read forbidden).

## 6. Adjudicator rulings (2026-11-17)

- J | floor-ok-with-condition | local state only, no network; Copy
  report writes the clipboard only on the player's click (decision 0014);
  redact the Windows user name, home path, sidecar path, contact value and
  character name; no chat / whisper text in the report; passive checks
  only (no probing of the game process; hotkey = "registered", never
  "pressed"); overlay / supervisor from server/al/procs.py, no window
  scan.
- K | floor-ok | opted-in Client.txt only, AshLight-authored text, no
  input, no game setting changed; the 3-load counter is in memory, the
  notice is dismissible and never claims the client is broken.
- L | floor-ok-with-condition | Client.txt events only; AshLight-authored
  text, no wiki / guide text bundled (decision 0009); store hint ids only,
  keyed by a hash of the character name (never the plain name) in
  gitignored ops/runtime; not tied to the run-history opt-in (ids carry no
  history) but nothing without Client.txt consent; a one-click "reset
  hints"; fallback without the file: per-session only.
- Record: alternatives rejected - L keyed by plain name (stores an
  identifier for no gain), L only under the run-history opt-in (hints
  would reappear without reason), J auto-upload report (floor-no: a
  network call outside the web_data opt-in). Reverses if decision 0003 or
  0013 changes, a report field leaks a path or identifier, or the
  operator wants the hint store tied to run history.
