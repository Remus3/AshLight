# AUDIT-46-CODE: code and repo audit, 2026-11-28

Scope: security (HTTP guard, hello HMAC, Electron guards / egress / app
scheme / IPC, update verification, calc confinement), correctness, dead
code, test gaps, repo hygiene, ToS floor. Read-only lane; checks run:
`python tools/leak_sweep.py --tree` (ARMED, 22 needles, no hit printed),
`python -m pytest -q tests/test_hello.py tests/test_ascii_lf.py` (8 passed;
whether the git-marked ASCII test ran inside that count is unconfirmed),
git grep sweeps listed per finding.

## Summary

No P1 finding. The HTTP guard (Host, Sec-Fetch-Site, Origin, constant-time
token, token-in-query only on /events), the hello handshake, the egress
lock, the al-app scheme resolver and the workflow pins / permissions all
read as specified in CLAUDE.md. The ToS sweep found one clipboard read
site (app/main.js:655, per press), no input synthesis outside a test probe
of AshLight's own window, no trade2 call and no network module outside the
known allow-listed fetchers. The findings are defence-in-depth gaps
(calc job object has no UI limits), one hygiene hole that could put a
secret-bearing temp file in a commit, an IPC check that is weaker than
its siblings, small correctness edges, a dead module group and a few test
gaps.

Count: 0 P1, 4 P2, 8 P3.

## Findings

### P2-1 Calc job object sets no UI restrictions (clipboard, desktop, handles)

- File: server/al/theorycraft/bridge.py:196-205 (Job.__init__)
- Evidence: LimitFlags are KILL_ON_JOB_CLOSE | ACTIVE_PROCESS |
  PROCESS_MEMORY only. No SetInformationJobObject call with
  JobObjectBasicUIRestrictions (class 4) exists in the file (grep for
  `UILIMIT` / `UIRestrictions`: zero hits). The no-clipboard / no-input
  guarantee for the luajit child rests only on the bridge.lua lockdown
  (ffi and package.loadlib removed). A future PoB pin that ships a native
  module reachable before the lockdown, or a lockdown regression, would
  let the child read the clipboard or post input to the foreground window
  (the game) with nothing at the OS layer stopping it. That is the ToS
  floor (clipboard only on a press; never input to the game).
- Fix: after the extended limits, set JOBOBJECT_BASIC_UI_RESTRICTIONS with
  UILIMIT_READCLIPBOARD | WRITECLIPBOARD | HANDLES | GLOBALATOMS | DESKTOP
  | DISPLAYSETTINGS | SYSTEMPARAMETERS | EXITWINDOWS; fail the start
  (BridgeUnavailable) if the call fails, like the other limits; extend
  Job.limits() and tests/test_tc_bridge.py to assert the UI mask.

### P2-2 Crash-left temp copies of config/local.json are not gitignored

- Files: .gitignore:3-6; server/al/jsonfile.py:116-121
- Evidence: jsonfile writes `<name>.tmp` or `<name>.<tag>.tmp` beside the
  target, so a crash between write and os.replace leaves
  `config/local.json.<pid>.<hex>.tmp` (the contact, hotkeys, settings).
  .gitignore lists only `config/local.json` and `config/local.json.bak`;
  there is no `*.tmp` rule. A `git add -A` would stage it; the leak sweep
  catches it only if the leftover holds a configured needle.
- Fix: add `config/local.json.*` (or `config/*.tmp` plus `*.tmp`) to
  .gitignore and a case to the test that checks .gitignore coverage
  (or tests/test_sidecar_paths.py) asserting `git check-ignore` matches a
  synthetic `config/local.json.1.ab.tmp`.

### P2-3 al:gate IPC checks the sender webContents, not the exact frame

- File: app/main.js:582-585
- Evidence: `if (!win || e.sender !== win.webContents) return;` while
  al:config (main.js:574) uses Guards.frameIsOverlayPage(e.senderFrame,
  ...) and CLAUDE.md (OVL-SHELL-GUARDS) states "IPC answers only the exact
  sender frame". A sub-frame or a navigated page in the overlay
  webContents would pass this check. Today the overlay CSP
  (app/pages.js cspFor: default-src 'none', frame-ancestors 'none') and
  the deny-all navigation policy make that unreachable, so the effect is
  inconsistency, not an exploit.
- Fix: use `Guards.frameIsOverlayPage(e.senderFrame, win, OVERLAY_URL)`
  for al:gate too, and add a guards test that a non-main frame sender is
  ignored.

### P2-4 Download name loop can overwrite a file after 99 collisions

- File: app/client/window.js:380-384
- Evidence: the loop stops at `i < 100`; when "name.ext" through
  "name (99).ext" all exist, `target` is left at "name (99).ext", which
  exists, and setSavePath overwrites it. Also check-then-set is racy if
  two downloads of one name start together (both may pick the same
  free name).
- Fix: after the loop, if fs.existsSync(target) fall back to a
  timestamped stem (`name-<Date.now()>.ext`) or cancel with a log line;
  keep a per-session Set of names handed out so two concurrent downloads
  never share one. Add a client.test.js case with 100 fake existing
  names.

### P3-1 Bridge child runs with the full user token

- File: server/al/theorycraft/bridge.py:510-535 (start path)
- Evidence: the job object bounds process count and memory, but the
  child keeps the player's full token; "no file writes from Lua" is only
  the bridge.lua lockdown. Unconfirmed whether a restricted or
  low-integrity token is feasible without admin rights for luajit.exe
  reading the PoB checkout.
- Fix: spike a low-integrity start (CreateRestrictedToken plus
  SetTokenInformation integrity level, stdlib ctypes) in a research note;
  adopt only if PoB still loads (reads stay allowed at low integrity;
  writes outside LocalLow are refused). Otherwise record the decision in
  0022.

### P3-2 Installer downloads have a per-socket timeout but no overall deadline

- File: server/al/install/payload.py:93-127 (installer_stream)
- Evidence: `opener.open(req, timeout=timeout)` and `resp.read(CHUNK)`
  bound each socket wait, but a server dripping one byte per timeout
  window keeps a staged update running indefinitely (bounded only by
  max_bytes). webfetch.read_body has a deadline (snapshot.py:285 passes
  deadline_at); this path does not. The opener also honours the system
  proxy (no ProxyHandler({})); the payload is hash-checked so this is a
  privacy, not an integrity, point. Unconfirmed whether
  pinfetch.ensure_runtime adds a deadline around it.
- Fix: pass a monotonic deadline (for example max(120 s, max_bytes / 256
  KB/s)) and raise FetchError past it, as webfetch.read_body does; add a
  test with a fake response that yields one byte per call.

### P3-3 Dead module group: gggapi, oauthlisten, ratelimit

- Files: server/al/gggapi.py, server/al/oauthlisten.py,
  server/al/ratelimit.py
- Evidence: no non-test file imports gggapi (its name appears only in
  itself, e.g. gggapi.py:320, and in tests/test_gggapi.py,
  tests/test_trade_link.py:145,154); oauthlisten and ratelimit are
  imported only by gggapi (gggapi.py:56). This matches decision 0048
  (OAuth client prepared, waiting on REG_OPEN), so it is intentional
  dormancy, not junk.
- Fix: none to the code; add one line to decision 0048 (or a module
  docstring) saying these three are dormant until REG_OPEN and are
  exempt from dead-code sweeps, so later audits do not re-flag them.

### P3-4 Four public functions used only by tests

- Files and lines: server/al/leagues.py:86 `id_of`

### P3-5 Install payload safety helpers have no direct unit tests

- File: server/al/install/payload.py:141 (safe_path), :289
  (_plan_members), :257 (check_zip_bytes), :474 (extract)
- Evidence: no test names them; tests/test_install_payload.py:332-346
  covers `..` and a symlink member only through install_payload.
  Reserved names (CON, NUL.txt), trailing dots, backslashes, drive
  letters, over-long paths and a mode-bits directory member are not
  exercised.
- Fix: add table-driven tests of safe_path (each refused shape and a
  few accepted ones) and a _plan_members test with a crafted ZipInfo
  set (duplicate names differing by case, a member outside the one top
  folder, a symlink mode).

### P3-6 egress originOf and LOG_CAP untested

- File: app/egress.js:64 (originOf), :34 (LOG_CAP)
- Evidence: app/test/egress.test.js uses allow and makeFilter only; no
  test asserts that a refused URL with a token in its query logs only
  scheme plus host, or that logging stops at 64 origins. The first is a
  token-leak guard.
- Fix: add two node tests: originOf("http://127.0.0.1:1/events?token=x")
  has no "token"; 70 distinct refused origins produce exactly LOG_CAP log
  lines.

### P3-7 ASCII / LF test skips ops/fleet_kit entirely

- File: tests/test_ascii_lf.py:66
- Evidence: every tracked text file is checked except paths under
  fleet_kit. The kit is byte-pinned by ops/fleet_kit/MANIFEST.json, so a
  local edit already fails conformance, but a kit version that ships a
  CRLF or non-ASCII file would land unnoticed against FLEET item 8.
- Fix: keep the skip (the tree must not edit kit files) but add a
  non-failing report, or a channel note to MAIN, when a kit file breaks
  ASCII / LF; report-only so the kit stays MAIN's to fix.

### P3-8 HEAD runs the full GET route

- File: server/al/http.py:397-398
- Evidence: do_HEAD calls do_GET, so a HEAD on a GET route runs its work
  (state build, iteminfo lookup, settings export) and only the body
  write is skipped (_send checks HEAD at :285). Token-gated, so no
  exposure; it is wasted work and a hidden side-effect path if a GET
  route ever gains one. The SSE route under HEAD is unconfirmed (it may
  hold a stream slot).
- Fix: answer HEAD with 405 for /events and the /api/ routes (keep it
  for static assets), or route HEAD through a table of allowed paths;
  add a test that HEAD /events returns at once without taking an
  sse_slots slot.
