# UX-46-REVIEW - six-lens UI/UX review, 2026-11-28

Scope: web/ (index.html, css, js, panels), app/overlay/, app/client starting
and failed pages (app/pages.js list), the install / first-run / update
notice flow (scripts/install.ps1, server/al/install/, region C setup card,
Settings > Reading and web data, Settings > About and data update block).
Lenses: UI/UX, visual, readability, comprehension, ease of use, ease of
setup. Measured against docs/design/0001-design-system.md (sections 2, 7,
8, 9) and the copy sheets in docs/design/copy/.

Read-only check run: `python -m pytest -q tests/test_copy_dead_ends.py`
(5 passed). No file other than this one was changed.

## Summary

The play surfaces (overlay HUD, card slot, Play cockpit) follow the system
closely: telegraphic overlay lines, honest empty states, no motion, word
plus glyph on every state. The weak spots are all on the way IN: the
failed start page, the first-run setup card, the web-data opt-in sentence
and the update notice. Three things can stop or mislead a first-time
player: the failed page tells an installed player to install Python, the
web-data opt-in sentence does not match what an installed copy actually
does (no poe.ninja prices; unnamed game-data downloads), and the setup card
names three optional steps without saying where any of them is done.
Internal words ("core") still leak into two player sentences, and several
Settings status sentences are one-line ellipsised, cutting off the step
the player needs.

Count: 3 P1, 9 P2, 7 P3 (19 findings).

## P1 - blocks or misleads a first-time player

### P1-1 Failed start page tells installed players to install Python
- Lens: comprehension, ease of setup
- File: app/client/starting.html:17
- Issue: when AshLight does not start, the general line says "check that
  Python 3.11 or newer is installed". An installed copy runs on its own
  private Python (decision 0063); installing Python does nothing for that
  player, so the one advice offered is a dead end. The same sentence also
  shows a raw environment-variable path
  (`%LOCALAPPDATA%\Programs\AshLight\logs`) that most players cannot read.
- Fix: let window.js pass the copy kind (installed vs checkout, already
  known from app/client/home.js) as a query value and show one of two
  fixed lines:
  - installed: "AshLight couldn't start. Open it again from its Start Menu
    shortcut. If it fails again, paste the install line from the README
    again; it repairs AshLight and keeps your settings. Details are in
    run.log in the logs folder of AshLight's install folder."
  - checkout: keep today's line.

### P1-2 Web-data opt-in sentence does not say what an installed copy does
- Lens: comprehension (principle 7, Honest), ease of use
- File: web/tc.js:147 (static twin web/index.html:824)
- Issue: the sentence the player ticks beside says "AshLight asks for
  three things only" and promises "currency and item prices from poe.ninja
  about once an hour". In an installed copy ninja.RELEASE_POLLING is off
  (server/al/ninja.py:115, decision 0072) so no price is ever fetched;
  the player learns this only after ticking ("This version of AshLight
  does not ask poe.ninja for prices."). The sentence also leaves out the
  game-data download the same switch starts (the snapshot tool reads
  repoe-fork and raw.githubusercontent.com, decisions 0009 / 0013), so
  "three things only" is not true either. The player's consent is given
  to a list that is wrong in both directions.
- Fix: build the sentence from the copy kind and list every request.
  Installed copy (release polling off): "Off unless you turn it on. When
  on, AshLight downloads game data (item bases, gems, the passive tree)
  from public GitHub pages once a day, opens a build link you paste,
  once, and checks GitHub once a day for a new AshLight, which downloads
  by itself and installs at a later start. This version asks poe.ninja
  for nothing; prices show as a trade link you open. It never asks the
  trade site anything. It sends no account, password or cookie, and never
  touches the game." Checkout: the same with the poe.ninja sentence
  ("It fetches currency and item prices from poe.ninja, currency hourly,
  the rest every 3 hours.") in place of "asks poe.ninja for nothing".
  Bump the wording version so earlier opt-ins re-acknowledge (decision
  0013 amendment already supports this). Drop the static twin text in
  index.html:824 to an empty element so the two cannot drift.

### P1-3 Setup card names three steps but no place to do them
- Lens: ease of setup, comprehension
- File: server/al/playcards.py:73-78 (fallback words web/setupcard.js:63-69)
- Issue: the first screen shows "Your build: not set, optional",
  "Prices: off, optional", "Overlay: off, optional" (or "not running,
  optional") with no control and no place named. A new player cannot tell
  how to load a build, where prices are turned on, or how to get the
  overlay. Section 8 rule 4 asks a sentence that sends the player
  somewhere to name the control and its place. In an installed copy the
  Prices step can never become "on" (P1-2), so it reads as a broken step.
- Fix: keep the rows control-free (one button rule) but give each its
  place, within CAP_ROW 52:
  - "Your build: optional - copy a PoB code, press <key>" (key from the
    published hotkeys view; with no key: "Your build: optional - paste it
    in Build and items")
  - checkout: "Prices: optional - Settings, Reading and web data";
    installed copy: "Prices: trade links only in this version"
  - "Overlay: optional - tray menu, Show in-game overlay"
  Add the exact strings to a copy sheet (a new `setup` section of
  docs/design/copy/overlaycard.md or its own sheet) with a unit test.

## P2 - friction

### P2-1 Setup card "Client.txt not found" hides the typed-path field
- Lens: ease of setup
- File: server/al/playcards.py:70 (web/setupcard.js:67), error rows
  web/setupcard.js:87-93
- Issue: with no log found the card says "Client.txt not found yet. Start
  the game once." and the error mode says "Open Checks to see where
  AshLight looks." The real fix for a moved or non-default install, the
  "Can't find Client.txt? Type the game folder..." field
  (web/index.html:773, shown while the log check fails), is never named.
  A player whose game already ran is told to do something that will not
  help.
- Fix: SETUP_NO_PATH = "Not found yet. Start the game, or type its folder
  in Settings." is 66 chars, so split: path row "Client.txt not found
  yet." and make the nopath error rows 4 and 5 "Start the game once so it
  writes the log." / "Or type the game folder in Settings, Reading." and
  the error button "Type the folder" jumping to #logpath-in (rail jump
  data-jump="logpath-in"), instead of "Open Checks".

### P2-2 "AshLight is not answering" sends the player to Checks
- Lens: comprehension, ease of use
- File: web/setupcard.js:95-101
- Issue: the lost mode's last row and its only button say "Open Checks if
  it stays like this." Checks is filled by the same AshLight that is not
  answering, so the button opens a stale list. Dead end.
- Fix: row 5 "If it stays like this, quit from the tray and reopen it." and
  no button in the lost mode (or a "Reload page" button calling
  location.reload(), which is an in-page action, not a modal).

### P2-3 "core" in two player sentences
- Lens: readability (principle 5, section 8 rule 4)
- File: app/client/window.js:162; server/al/text/explain.py:98
- Issue: "AshLight stopped restarting its core after 3 tries (...)" on the
  failed page and "AshLight restarted its core {n} times in the last 24
  hours" in Checks / the report use the banned internal word.
- Fix: "AshLight stopped trying to restart after 3 tries (it had stopped
  answering)." and "AshLight restarted itself {n} times in the last 24
  hours, last at {clock} ({why})." Add "core" to the scan list of
  tests/test_copy_dead_ends.py or a sibling copy test for app/client and
  server/al/text.

### P2-4 Settings status sentences are cut with an ellipsis
- Lens: readability, visual
- File: web/index.html:795 (#webdata-status ... one-line), web/app.css:762
- Issue: #webdata-status carries the "one-line" class, so in the cockpit
  size classes it is nowrap plus ellipsis, with no title. Its longest
  sentences ("Web data is on. This copy has no default contact, so prices
  need one more step: add your contact for poe.ninja below." 116 chars,
  CONTACT_REFUSED, LEAGUE_REFUSED) lose exactly the step at the end.
  Section 9 rule 6: "Dashboard sentences outside Play wrap, never
  truncate." The same pattern sits on #watch-said (web/index.html:424).
- Fix: drop "one-line" from #webdata-status and the other Settings and
  card-page status spans (they already sit in a flex-wrap .set-row, so
  they take their own line); keep the 32 px row minimum. Add a
  tests/test_play_fit-style check that no element with role=status or a
  "-status"/"-said" id outside Play carries one-line.

### P2-5 Update notice in click-only mode does not mention Update now
- Lens: comprehension, ease of use
- File: web/updates.js:171
- Issue: with "Update only when I click Update now" ticked and a newer
  release, the line reads "AshLight 0.3.0 is out. See what changed on
  GitHub." while an "Update now" button sits under it. The line points
  away from the one action that installs it.
- Fix: "AshLight 0.3.0 is out. Click Update now to install it." (54 chars,
  under LINE_MAX 94); the releases link below already covers "what
  changed". In a checkout (no button) keep the GitHub wording.

### P2-6 "Off" update lines do not say where web data is
- Lens: ease of use (section 8 rule 4)
- File: web/updates.js:77, web/updates.js:99
- Issue: "Update checks are off while web data is off." and "Turn on web
  data to update." name a setting but not its place; About and data is a
  different Settings section from Reading and web data.
- Fix: "Update checks are off while web data is off. Turn it on in
  Settings, Reading and web data." (93 chars) and NOW_SAID.off "Turn on
  web data in Settings, Reading and web data first." Optionally add a
  secondary btn-24 "Web data" with data-jump="webdata-on", the same jump
  the Prices card uses (web/index.html:417).

### P2-7 "installs at a later start" is vague
- Lens: comprehension
- File: web/updates.js:168, web/updates.js:174, web/tc.js:150
- Issue: "It installs at a later start" / "installs by itself at a later
  start" does not tell the player when. Decision 0065 says: the next
  client start after a 24 h hold, only while the game is closed.
- Fix: "AshLight 0.3.0 is downloaded. It installs the next time you open
  AshLight, a day after it came out." (90 chars) and for the not-yet
  downloaded case "AshLight 0.3.0 is out. It downloads while the game is
  closed and installs on a later start." (91 chars). Use the same "next
  time you open AshLight" phrase in the opt-in sentence.

### P2-8 Installer ends with step logs, not a next step
- Lens: ease of setup
- File: scripts/install.ps1:349, :357, :360; server/al/install/install.py:351-353
- Issue: success ends with "install: done (0.1.0)" and "AshLight
  installer: done"; failure ends with "stopped: HTTP 404 from github.com"
  or "the installer stopped with code 3; its report is
  <home>\logs\reports\last-install.json" (a literal "<home>"). Neither
  says what the player should do next or whether anything was left
  installed.
- Fix: success: "AshLight installer: AshLight is installed and opening
  now. Next time, start it from the AshLight shortcut in the Start Menu."
  Download failure (before hand-over): "AshLight installer: stopped:
  <reason>. Nothing was installed. Check your internet connection and
  paste the line again." Hand-over failure: print the resolved home path
  instead of "<home>" (console output is not app text, so a path is
  allowed), plus "Paste the line again to retry; it repairs in place."

### P2-9 Build fix line says "the item key" without the key
- Lens: ease of use, comprehension
- File: server/al/playview.py:93
- Issue: "Copy a PoB code, press the item key." A first-time player does
  not know which key that is; every other surface prints the effective
  key (decision 0058: "every surface prints those, never a literal").
- Fix: compose from the published hotkeys view: "Copy a PoB code, press
  <key>" (34 chars with Alt+Shift+E, under the 36 build-row cap); over the
  cap or with no key known: "Copy a PoB code, then check it".

## P3 - polish

### P3-1 Release price text gives no next step
- Lens: comprehension
- File: web/prices.js:60
- Issue: "This version of AshLight does not ask poe.ninja for prices." says
  what is missing but not what the player gets instead.
- Fix: "This version of AshLight does not ask poe.ninja for prices. Item
  checks give a trade link you can open."

### P3-2 Contact field shown where it does nothing
- Lens: UI/UX
- File: web/prices.js:82-91 (contactView), web/index.html:802-811
- Issue: in an installed copy no poe.ninja request is made, yet the
  "Your contact for poe.ninja" field, Save button and a three-sentence
  note still show once web data is on. It invites a step with no effect.
- Fix: contactView returns show false while the answer's blocked reason
  is "release build"; a saved contact keeps its Clear button only.

### P3-3 Restart words say "send it to the project" with no place
- Lens: ease of use
- File: server/al/text/explain.py:100
- Issue: "copy this report and send it to the project" - where?
- Fix: "... copy this report and add it to a new issue on the AshLight
  issues page." and, when update.releases_url / the issues URL is known,
  show the issues link beside Copy report (github.com is in
  config/link_hosts.json).

### P3-4 Setup ask repeats "read"
- Lens: readability
- File: server/al/playcards.py:69, :72 (web/setupcard.js:66, :68)
- Issue: "Let AshLight read the game's log, read only:" then the button
  "Allow reading Client.txt" and the promise "Read only. Play in Windowed
  Fullscreen." - "read" three times in four lines, and the colon leads
  into a path row that may say "not found".
- Fix: SETUP_ASK = "AshLight follows your game through its log file." and
  keep the promise line "Read only. Play in Windowed Fullscreen." as the
  one place that says read only.

### P3-5 Feed empty text says "above" in every layout
- Lens: comprehension
- File: web/status.js:316
- Issue: "Allow reading Client.txt above, then ..." assumes the setup card
  sits above the feed; in the flow class and on narrow widths the order
  follows DOM order, but a direction word ages badly with layout changes.
- Fix: "Nothing yet. Allow reading Client.txt in Right now, then zones,
  level-ups, deaths and whispers show up here." or drop the direction:
  "Nothing yet. Once AshLight may read Client.txt, zones, level-ups,
  deaths and whispers show up here."

### P3-6 README is out of step with the app
- Lens: ease of setup
- File: README.md:204-205, README.md:315, README.md:337
- Issue: README says the contact is needed ("without it price fetches stay
  off"), but DATA-CONTACT-DEFAULT sends the issues page by default; it
  says "Automatic update is not finished yet" while Settings already
  shows Update now and auto-install; "open Settings, then Apps" can be
  read as AshLight's own Settings tab.
- Fix: "`contact` (optional; how poe.ninja can reach you, sent in the
  User-Agent; without it AshLight sends its issues page)"; replace the
  Update section with the shipped behaviour (daily check with web data on,
  download while the game is closed, install a day later at the next
  start, Update now in Settings, About and data); "open Windows Settings,
  then Apps, then Installed apps". Add a docs_fresh fact for the update
  wording if cheap.

### P3-7 Update now restarts AshLight mid-play without saying so
- Lens: UI/UX (principle 3, quiet)
- File: web/updates.js:95-96, web/index.html:1065
- Issue: Update now skips the game-idle gate (REL-UPDATE-TRIGGER), and the
  staged path restarts AshLight "in a moment", so the overlay vanishes
  if the player clicks it while playing. Nothing before the click says so.
- Fix: a muted line beside the button, shown only while game_idle is not
  true: "AshLight closes for about a minute to update. Best while the game
  is closed." No confirm dialog (section 7.1).
