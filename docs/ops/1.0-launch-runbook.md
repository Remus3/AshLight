# PoE2 1.0 launch runbook (UTIL-1.0-POST)

Status: ready, waiting on the launch (PoE2 1.0, 2026-12-11). Row:
ROADMAP `UTIL-1.0-POST` (stays BLOCKED until launch day). Filed by
DOC-1.0-RUNBOOK, 2026-11-17. Sources: research 0021 section 3 (the
checklist), ROADMAP UTIL-1.0-POST PRE-VERIFIED (what the synthetic 1.0 log
already proves), decisions 0004, 0009, 0013, 0018, 0020, 0030.

Goal: launch day is mechanical. Each step below names the files and tests
it touches, the exact commands, and the read-back that proves it. Run the
steps in order; steps 1-3 need the real 1.0 Client.txt, so play the first
1.0 session (any character, into Act 5) before step 2.

All commands run from the repo root in a lane worktree (never edit main
directly). `<Client.txt>` is the player's real log path (the one the
dashboard consent card shows; per-host value, never committed).
`<id>` is the gate owner id (`<session_id>.<agent_id>`).

Floor reminders (CLAUDE.md, non-negotiable): no game file is written, no
input is sent to the game, web fetches only under the opt-in (decision
0013) or the explicit build `-Snapshot` force, every fetch carries the
truthful User-Agent. Fixture lines are copied from the log text only after
removing character names, account names and whisper text (sanitised; the
synthetic fixture shows the shape).

## 2. Survey the first 1.0 log (checklist item 2, the "debug sink")

The parser already turns every system line it does not know into an
`unknown_system_line` event (server/al/parser.py `_system`), shown on the
dashboard as "Something happened in the log". That is the debug sink;
nothing new has to be built.

- Touches: `tests/fixtures/client_10_shapes.txt` (replace GUESS lines with
  sanitised real lines, keep the GUESS mark on anything still guessed),
  `tests/test_util_10_fixtures.py`, and, only for a line worth showing,
  `server/al/parser.py` plus `tests/test_parser.py`.
- Command, unknown system lines with counts:

  ```
  python -c "import collections,sys; from server.al import parser; c=collections.Counter(); [c.update([e['body'][:120]]) for e in (parser.parse_line(l) for l in open(sys.argv[1],encoding='utf-8',errors='replace')) if e and e.get('type')=='unknown_system_line']; [print(n,b) for b,n in c.most_common(200)]" "<Client.txt>"
  ```

- Command, every area id with its scene name (feeds steps 3 and 5):

  ```
  python -c "import collections,sys; from server.al import parser; c=collections.Counter(); [c.update([(e.get('type'), str(e.get('area_id') or e.get('scene') or ''))]) for e in (parser.parse_line(l) for l in open(sys.argv[1],encoding='utf-8',errors='replace')) if e and e.get('type') in ('area_generated','scene_changed')]; [print(n,k) for k,n in sorted(c.items())]" "<Client.txt>"
  ```

- Do: for each new line shape (Conquerors of Wraeclast battles,
  stronghold, Acts 5-6 scenes, any death summary) add one sanitised line
  to the fixture and assert what it folds to. Teach the parser a line
  only when the dashboard should say something specific about it.
- Verify: `python -m pytest -q tests/test_util_10_fixtures.py tests/test_parser.py`
  passes; re-run the first command on the fixture and every remaining
  unknown line is one you chose to leave unknown.
